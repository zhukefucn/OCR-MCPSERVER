# OCR MCP Server 安装与部署手册

## 1. 适用环境

生产环境：

- Ubuntu Server
- Python 3.11
- Docker Engine 与 Docker Compose V2
- NVIDIA RTX 5090 32GB
- NVIDIA 驱动、Container Toolkit 和可用的 CUDA 运行时
- 64GB 内存

开发机可以使用 Windows 或 Linux。本机只编写代码和运行基础测试，GPU 镜像只在
Ubuntu 5090 服务器构建。

## 2. 获取代码

```bash
git clone https://github.com/zhukefucn/OCR-MCPSERVER.git
cd OCR-MCPSERVER
git checkout release/ocr-mcpserver-0.1.0
```

发布前确认工作区没有未提交文件：

```bash
git status --short
git rev-parse HEAD
```

## 3. 本机开发环境

```bash
uv venv --python 3.11
source .venv/bin/activate
uv pip install -e ".[dev]"
python -m pytest -q
```

Windows PowerShell：

```powershell
uv venv --python 3.11
.\.venv\Scripts\Activate.ps1
uv pip install -e ".[dev]"
python -m pytest -q
```

## 4. 准备模型

以下目录不提交模型权重，只保存挂载位置：

```text
models/
├── mineru-vlm/
└── pp-structure-v3/
    ├── pp-structure-v3.yaml
    ├── model-manifest.json
    └── doc-orientation/
```

要求：

- MinerU 模型快照放在 `models/mineru-vlm/`。
- PP-StructureV3 完整离线模型包放在 `models/pp-structure-v3/`。
- `model-manifest.json` 必须记录模型文件相对路径和 SHA-256。
- 模型目录以只读方式挂载。
- 生产启动时不得访问网络下载权重。

## 5. 配置生产变量

不要把真实值写入 Git。通过当前 shell、系统密钥管理器或受保护的环境文件注入：

```bash
export OCR_GATEWAY_PORT=18011
export OCR_PUBLIC_BASE_URL='https://ocr.example.com'
read -rsp 'OCR API Key: ' OCR_AUTH__API_KEYS
export OCR_AUTH__API_KEYS
printf '\n'
```

主要变量：

| 变量 | 说明 |
|---|---|
| `OCR_GATEWAY_PORT` | 主机监听端口，当前验证端口为 `18011` |
| `OCR_PUBLIC_BASE_URL` | 对外可访问的 HTTPS 地址 |
| `OCR_AUTH__API_KEYS` | REST 和 MCP 鉴权密钥 |
| `OCR_DATA_ROOT` | 容器内数据目录，生产固定为 `/data` |
| `OCR_LIMITS__MAX_FILE_SIZE_BYTES` | 单文件上限，默认 `62914560` |

## 6. 构建镜像

在 Ubuntu 仓库根目录执行：

```bash
docker compose build mineru-vlm mineru-api ocr-production
```

默认生产路径只使用：

- `mineru-vlm`
- `mineru-api`
- `ocr-production`

`paddleocr_vl` 属于实验镜像，不进入默认生产路径。

## 7. 启动服务

```bash
docker compose up -d mineru-vlm mineru-api ocr-production
docker compose ps
```

确认：

- 三个容器均为运行状态。
- `ocr-production` 为 `healthy`。
- 端口映射为 `${OCR_GATEWAY_PORT}:8000`。
- 数据卷 `ocr-data` 已挂载到 `/data`。

## 8. 启动验证

存活检查：

```bash
curl -fsS http://127.0.0.1:${OCR_GATEWAY_PORT}/health/live
```

完整发布验证：

```bash
export OCR_VERIFY_API_KEY="${OCR_AUTH__API_KEYS}"
GIT_SHA="$(git rev-parse HEAD)"
RUN_ID="$(python scripts/verify_deployment.py --derive-run-id --git-sha "$GIT_SHA")"
python scripts/verify_deployment.py --phase static --run-id "$RUN_ID"
python scripts/verify_deployment.py --phase runtime --run-id "$RUN_ID"
python scripts/verify_deployment.py --phase e2e --run-id "$RUN_ID"
```

验证程序只输出有限状态、计数和错误码，不输出正文、文件名、路径、URL 或密钥。

## 9. 固定镜像版本

只有本机全量测试、远程健康检查和真实文件回归全部通过后才能固定版本：

```bash
GIT_SHA="$(git rev-parse HEAD)"
docker tag ocr-mcp-server:production-dev \
  "ocr-mcp-server:production-${GIT_SHA}"
docker image inspect "ocr-mcp-server:production-${GIT_SHA}" \
  --format '{{.Id}} {{.Created}}'
```

把提交、镜像 ID、验证时间和验证集合记录到：

```text
deployments/ocr-mcp-server/<git-sha>.env
```

## 10. 升级与回滚

升级顺序固定为：

1. 本机运行全量测试。
2. 推送已提交代码。
3. Ubuntu 同步到明确提交。
4. 构建候选镜像。
5. 立即启动并检查健康。
6. 运行真实回归文件。
7. 固定不可变镜像标签。

回滚时选择上一个 `deployments/ocr-mcp-server/` 记录中的镜像标签，重新创建
`ocr-production`。SQLite 数据卷和产物目录不得删除。

## 11. 数据与权限

- `/data` 只允许 OCR 服务账号写入。
- 输入、中间文件和结果默认保留 24 小时。
- 无正文审计元数据保留 30 天。
- 不把测试 PDF、产物 ZIP、模型权重或 `.env` 文件提交到仓库。
- 不执行 `docker compose down -v`，除非明确要求永久删除所有 OCR 数据。
