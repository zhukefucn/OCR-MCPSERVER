# 银行业文档 OCR MCP Server 系统设计规格

## 1. 目标

把 MinerU 与 PaddleOCR 封装成适合智能体使用的通用 OCR 能力层。智能体只提交文档、
查询进度和在用户确认后执行方向恢复，不参与底层引擎选择、重试、候选路由、合并或
打包。

## 2. 总体架构

```text
REST / MCP
    │
    ▼
ocr-gateway（FastAPI）
    ├── 文件安全接入
    ├── SQLite 任务状态与进度
    ├── Stage 0 输入预处理
    ├── MinerU 编排
    ├── Paddle 二次检测
    ├── 结果合并
    └── 产物校验、打包和发布
          │
          ├── mineru-api
          │      └── 固定 vlm-http-client
          └── mineru-vlm
                 └── mineru-openai-server
```

## 3. 固定策略

- 主解析引擎固定为 MinerU。
- MinerU 固定使用 `vlm-http-client`。
- VLM 推理运行在独立 `mineru-vlm` 容器。
- 默认二次检测引擎为 PP-StructureV3。
- PaddleOCR-VL 只作为独立实验镜像，不进入默认生产路径。
- 不允许请求或智能体选择引擎。
- 不执行运行时自动引擎切换。

## 4. 输入与容量

| 项目 | 约束 |
|---|---|
| 文件类型 | PDF、PNG、JPG、JPEG |
| 单文件大小 | 最大 60 MiB |
| 单文件页数 | 最大 500 页 |
| 单批次文件数 | 最大 20 |
| 单批次总量 | 最大 1 GiB |
| 加密 PDF | 不支持 |

## 5. Stage 0 预处理

- 原始上传文件不可变。
- 派生文件放在 `intermediate/<file_id>/preprocessed/`。
- 正常文件零复制，直接使用原路径。
- 长图片先按高宽比筛选，再根据横向留白带切分并生成多页 PDF。
- 整份 PDF 侧倒时，只低分辨率渲染第一页进行方向分类；高置信度时把同一无损旋转
  写入全部 PDF 页。
- 低置信度方向结果保持原文件并记录警告。
- 预处理清单记录版本、分类、输入/输出 SHA-256、源页数、准备页数、旋转和切分位置。
- 重试只有在源哈希和预处理器版本一致时复用派生文件。

原始审计使用 `source_page_count`；MinerU、进度和候选收集使用
`prepared_page_count`，两者不得混淆。

## 6. MinerU 与 Paddle 路由

- MinerU 导出的每个图片候选都执行 Paddle 二次检测。
- 表格和公式只有通过有效性校验后才替换原图片引用。
- 图片中存在可信文字时，把文字回填到最终 Markdown；纯 Logo、示意图和普通图片
  保持图片引用。
- 局部旋转候选先显式执行方向分类、确定性旋转，再交给 Paddle。
- 整页旋转异常且页面为混合版面时，生成单页 PDF，最多重跑一次 MinerU。
- 纯表格整页可以使用 Paddle 表格结果替换。
- 禁止 MinerU 与 Paddle 循环重试。

当异常页数量达到 `max(3, ceil(total_pages * 0.15))` 时，返回文档级方向纠正，
不逐页重试。

## 7. 合并优先级

1. MinerU 单页方向重试结果替换原页面。
2. Paddle 只替换通过校验的表格、公式、可信图片文字或明确纯表格整页。
3. 普通图片保持原样。
4. 不任意混合两个整页结果。
5. 原始 MinerU 快照、合并结果和二次识别审计分别保存。

## 8. 对外接口

### REST

- 文件上传
- 任务创建和查询
- 产物下载
- 存活、就绪和指标接口

### MCP

- `parse_documents`
- `get_task_status`
- `reparse_with_page_orientation`

MCP 不接受本地路径。本地文件由客户端或 Skill 先通过 REST 上传取得 `file_id`。

## 9. 状态与持久化

- SQLite 保存批次、文件任务、租约、重试、进度、产物和恢复状态。
- 使用本地挂载目录保存输入、中间文件和结果。
- 不引入 Redis、PostgreSQL 或外部消息队列。
- 单个 Paddle 模型由单一所有者 worker 持有，避免并发重复加载。

## 10. 产物

最终产物至少包括：

- `final.md`
- `content_list_v2.json`
- `original_content_list_v2.json`
- `secondary_ocr_audit.json`
- `artifact_manifest.json`
- `images/`
- 受控的 MinerU 原始文件

打包前验证 Markdown、JSON、图片路径、归档条目数、单条目大小和总大小。任何一个
非法结构不得导致静默丢失正文。

## 11. 安全

- 日志和指标禁止业务正文、OCR 文本、文件名、URL、路径、凭据和恢复令牌。
- 远程 URL 只允许 HTTPS 白名单。
- 每次重定向重新校验域名和目标地址。
- 拒绝私网、回环、链路本地和保留地址。
- 流式下载执行字节上限。
- API Key 只通过安全环境注入。
- 模型目录只读，生产启动不下载权重。
- 输入、中间文件和结果保留 24 小时；无正文审计元数据保留 30 天。

## 12. 部署

- Ubuntu Server、Python 3.11。
- RTX 5090 32GB、64GB RAM、i9-14900K。
- MinerU VLM、MinerU API 和 OCR Gateway 分容器部署。
- 本机测试通过后才同步 Ubuntu。
- Ubuntu 构建后立即启动验证。
- 健康和真实文件回归通过后才固定 Git SHA 镜像标签。

## 13. 已验证行为

- 60 MiB 文件边界。
- MinerU 空图片引用和空表格降级。
- MinerU V2 标题、脚注和列表结构。
- 图片文字二次识别和回填。
- 安全转义百分数公式。
- 462 页 PDF 的完整解析、811 个图片候选处理和产物打包。
