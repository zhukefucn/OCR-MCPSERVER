# 保留期清理子项名称绑定设计

## 目标

防止清理程序打开普通文件后，父目录中的原名称被并发重命名或替换，导致程序擦除已被
移动的原文件；同时保留硬链接拒绝和 Windows 独占句柄保护。

## 根因

POSIX 路径通过已固定的父目录描述符打开子项，但旧实现进入截断前只验证打开描述符的
身份，没有重新证明父目录中的原名称仍指向同一对象。并发重命名后，`fstat` 仍能证明
描述符是原对象，却不能证明原名称仍绑定该对象，因此可能先截断被移动的原文件，再在
后续目录验证中发现名称变化。

## 绑定契约

`_scrub_regular` 必须把固定的父目录描述符和已验证子项名称传给
`_scrub_open_regular`。执行 `ftruncate` 前必须同时证明：

- 打开的描述符是非重解析点普通文件，身份等于 `expected`，链接数为 1。
- POSIX 下，从固定父目录描述符以“不跟随链接”方式解析当前子项名称，得到的仍是
  非重解析点普通文件，身份等于 `expected`。
- 名称解析身份与打开描述符身份一致。
- Windows 下，当前绝对名称、句柄最终路径和预期身份三者一致。

任一不匹配必须在修改原文件或替换文件之前抛出
`cleanup_ownership_invalid`。截断并 `fsync` 后再次验证描述符身份、链接数、大小和
平台允许的名称绑定。

## 兼容性

- 不改变目录固定、墓碑状态、删除顺序或重试元数据。
- 单链接要求继续强制执行。
- Windows 独占父目录句柄和最终路径验证继续保留；名称绑定验证只做补充。

## 测试

- 并发重命名已打开文件并创建同名替换文件时，两份字节都保持不变。
- 截断前名称绑定不匹配直接失败。
- 硬链接隔离和 Windows 名称竞争回归继续通过。
- Linux、Windows 相关保留期测试和全量测试通过。

## 范围

只修改普通文件擦除和相关测试。不修改产物发布、标记恢复、保留时间、外部 API 或
部署行为。
