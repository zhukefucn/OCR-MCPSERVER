# MinerU 空图片引用兼容设计

## 背景

Ubuntu 5090 上的真实数据测试显示：

- `report-006.pdf` 的 2 页主流程成功完成；
- `report-002-xz.pdf` 的 MinerU VLM 主解析成功完成 23 页；
- MinerU 产物包含 Markdown、内容清单、middle JSON 和图片目录；
- `document_content_list_v2.json` 的第 20 页表格节点包含精确路径
  `images/`；
- 该值来自 MinerU 在表格 `image_path` 为空时拼接图片目录前缀，不表示一
  张图片文件；
- 当前候选收集器将其作为普通文件路径校验，最终以
  `candidate_path_unsafe_or_missing` 终止整个任务。

同一产物中有 45 个带有效文件名的图片引用。这些引用必须继续逐一进入
Paddle 二次检测。图片目录中另有 1 个没有被 legacy 内容清单、v2 内容清单
或 middle JSON 引用的 JPEG 文件，系统无法安全地将它绑定到某个文档节点。

## 目标

兼容 MinerU 生成的精确 `images/` 空图片引用，使主任务能够继续处理所有有
效图片候选，同时保持现有路径安全边界和结果替换规则。

## 非目标

- 不扫描图片目录来猜测空引用与孤立文件之间的对应关系。
- 不把未被 MinerU 清单引用的孤立文件绑定到任意节点。
- 不放宽绝对路径、父目录、反斜杠、空路径段、目录、符号链接、缺失文件或
  非常规文件的拒绝规则。
- 不改变 MinerU 主解析引擎、Paddle 引擎选择、旋转恢复流程或 API 合约。
- 不对业务正文或识别文本增加日志。

## 方案

候选收集器解析 `document_content_list_v2.json` 时，对
`image_source.path` 执行以下顺序：

1. 如果值不是非空字符串，继续按 `candidate_manifest_invalid` 拒绝。
2. 如果值精确等于 ASCII 字符串 `images/`，将该节点视为“没有可用图片文
   件的 MinerU 节点”，不为该引用创建图片候选，然后继续处理后续节点。
3. 其他任何值继续进入现有的路径规范化、目录约束、文件类型、图片格式、
   像素数和内容稳定性校验。

跳过空引用不会删除或改写 MinerU 清单中的节点。最终 Markdown、JSON 和
MinerU 原始图片仍按现有打包规则保留。由于该节点没有有效图片候选，Paddle
不会为它生成替换结果，合并阶段也不会替换该节点。

所有具有有效文件路径的图片引用继续保持现有行为：

- 按内容去重并保留全部节点引用；
- 每个唯一候选执行 Paddle `pp_structure_v3` 二次检测；
- 只有有效表格或公式结果才允许替换原图片引用；
- 其他图片保持原样。

## 安全边界

豁免只匹配精确字符串 `images/`。以下示例仍必须失败：

- `images`
- `images//`
- `images/../x.jpg`
- `/images/x.jpg`
- `images\x.jpg` 或任何反斜杠路径
- `images/missing.jpg`
- 指向目录、符号链接或非普通文件的路径

孤立图片文件不参与候选生成。这样可以避免依靠文件名排序、ZIP 条目顺序、
页面位置或图片尺寸进行不可靠映射。

## 错误处理与可观测性

- 精确空引用是受支持的 MinerU 输出形态，不应使任务失败。
- 其他异常继续使用现有安全错误码，不向 REST、MCP 或日志暴露原始路径及
  文档内容。
- 本次 MVP 不新增包含文件名或正文的日志。
- 如需统计，可在后续单独增加无内容计数指标；本次修复不扩大范围。

## 测试设计

候选收集单元测试至少覆盖：

1. 清单同时包含精确 `images/` 和一个有效图片路径时，仅生成有效图片候选。
2. 精确空引用对应的节点不出现在任何候选引用中。
3. `images//`、缺失文件和目录路径仍按原安全错误失败。
4. 现有“每个有效引用都被收集、去重和保留引用顺序”的测试继续通过。

验证顺序：

1. 新回归测试先在未修改实现上失败。
2. 最小实现使目标测试通过。
3. 运行候选收集相关测试。
4. 运行本机完整测试套件。
5. 同步 Ubuntu 5090，重新构建并立即启动验证。
6. 重跑部署门禁。
7. 重新提交 `report-002-xz.pdf`，确认主任务完成并检查是否返回旋转恢复
   `recovery_token`。
8. 验证通过后固定新镜像版本并写入新的不可变部署记录。

## 验收标准

- `report-006.pdf` 仍能完成并生成有效 ZIP。
- `report-002-xz.pdf` 不再因精确 `images/` 空引用失败。
- 45 个有效引用仍进入现有候选收集和 Paddle 流程。
- 未引用的孤立 JPEG 不被猜测绑定或用于替换。
- 除精确 `images/` 外的路径安全行为没有变化。
- 本机测试、Ubuntu 启动验证和部署门禁全部通过。
