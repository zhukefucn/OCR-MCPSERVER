# MinerU V2 产物打包兼容性修复设计

## 背景

`462pages.pdf` 已完成 MinerU 解析、811 个图片候选二次识别和结果合并，但在 Markdown 产物打包阶段失败。只读取结构与统计信息后的稳定复现表明，输入文件大小、页数、加密状态和归档限制均不是原因。

## 根因

1. MinerU V2 的列表节点使用 `content.list_type = "text_list"`，列表项位于 `content.list_items[*].item_content`，其中内容仍是标准行内 span 列表。现有渲染器只接受列表节点的 `text` 或 `text_content` 字符串。
2. MinerU 输出的百分数公式使用合法的转义百分号 `\%`。现有 LaTeX 校验器只要发现任意 `%` 就拒绝，因而把安全输入误判为非法内容。

## 方案比较

### 方案一：在消费边界显式兼容（采用）

- `validate_formula_latex` 允许奇数个反斜杠转义的 `%`，继续拒绝裸 `%`。
- `render_markdown` 显式识别 MinerU V2 的 `text_list/list_items/item_content`，复用现有行内 span 渲染和校验逻辑。
- 旧版 `text/text_content` 列表继续兼容。

优点是保留安全边界、原始审计 JSON 不变，改动范围最小。

### 方案二：全局允许所有百分号（不采用）

改动最小，但裸 `%` 在 TeX 中具有注释语义，会降低结构化内容安全校验强度。

### 方案三：在合并阶段改写 MinerU JSON（不采用）

会使原始解析结果和发布结果产生额外差异，并把展示层兼容逻辑扩散到结果合并层。

## 数据与错误处理

- V2 列表必须是非空 `list_items` 数组。
- 每个列表项必须是映射，且 `item_type` 必须为 `text`。
- `item_content` 必须能通过既有行内 span 校验；文本按 Markdown 规则转义，行内公式继续通过 LaTeX 校验。
- 不认识的 span 类型沿用现有行为：忽略该 span，并在产物警告中记录存在省略。
- 裸 `%`、危险 TeX 命令、非法环境、括号不平衡和重复攻击模式继续失败关闭。

## 测试与验收

1. 单元测试证明 `\%` 被接受、裸 `%` 仍被拒绝。
2. Markdown 渲染测试证明 V2 多项列表可输出，每项独占一行，并能包含安全的百分数行内公式。
3. 先观察新增测试在旧实现上按预期失败，再实现最小修复。
4. 本机运行目标测试和全量测试。
5. 推送后在 Ubuntu 5090 构建新镜像，启动并检查健康状态。
6. 用 `462pages.pdf` 重新执行端到端任务，要求产物成功生成、可下载且 Markdown 页数结构完整。

## 范围外事项

- 不修改 MinerU、PaddleOCR、候选收集或合并策略。
- 不改写原始或中间 JSON。
- 不放宽其他 LaTeX/HTML 安全规则。
- 不把当前未提交的 Stage 0 预处理原型混入本次提交。
