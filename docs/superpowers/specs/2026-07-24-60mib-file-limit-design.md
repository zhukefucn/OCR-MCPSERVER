# OCR MCP Server 单文件 60MiB 上限扩容设计

## 目标

将系统默认单文件大小上限从 30MiB 提升到 60MiB，即
62,914,560 字节。单文件最多 500 页、单批次最多 20 个文件、批次总量
最多 1GiB 等限制保持不变。

## 变更范围

服务级容量常量、默认配置、示例配置和部署配置统一使用 60MiB。上传请求的
`Content-Length` 预检和流式读取累计校验继续共用同一配置值，超过上限时仍
返回 HTTP 413 和稳定的 `capacity_exceeded` 错误，不记录文件正文。

文件接入、远程导入、不可变旋转衍生文件和旋转恢复后的新任务都必须接受
不超过 60MiB 的输入。清除旋转恢复数据模型和文档修正器中残留的 30MiB
默认值，避免文件可以上传却无法完成方向恢复。

已有显式配置为 30MiB 的外部部署不会因为代码默认值而被静默覆盖；本项目
随附的 Ubuntu 生产配置会明确更新为 60MiB。

## 页面旋转能力边界

本次只调整文件容量，不改变已确认的页面方向策略。正常解析完成后评估页面
方向并报告疑似页；只有调用 REST `POST /v1/orientation-reparse` 或 MCP
`reparse_with_page_orientation` 后，系统才校验 90°、180°、270° 修正角度，
生成不可变的新 PDF 并重新运行完整 OCR 流程。

## 测试与发布

先增加会在 30MiB 默认值下失败的容量回归测试，覆盖默认配置、上传边界和
旋转恢复提交边界；确认测试失败后再修改生产代码。随后运行完整本地测试。

本地通过后将提交同步到 5090 Ubuntu，构建新的候选镜像并立即启动验证。
远程验证至少包括健康检查、60MiB 配置生效检查、合成 PDF 端到端解析和产物
下载。获得真实样本后，另行验证接近 60MiB 的银行 PDF，以及包含 90°/270°
页面的多页 PDF。验证通过后才固定带 Git 提交号的镜像版本。
