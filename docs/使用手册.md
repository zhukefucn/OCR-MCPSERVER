# OCR MCP Server 使用手册

## 1. 支持范围

| 项目 | 限制 |
|---|---|
| 文件类型 | PDF、PNG、JPG、JPEG |
| 单文件大小 | 最大 60 MiB |
| PDF 页数 | 最大 500 页 |
| 单批次文件数 | 最大 20 |
| 单批次总量 | 最大 1 GiB |
| 加密 PDF | 不支持 |

## 2. 鉴权

REST 和 MCP 使用同一 API Key。只通过环境变量传递：

```powershell
$env:OCR_MCP_API_KEY = '<密钥>'
```

```bash
export OCR_MCP_API_KEY='<密钥>'
```

不要在聊天、命令历史、日志或配置仓库中回显真实密钥。

## 3. REST API 工作流

### 3.1 上传本地文件

```bash
curl -X POST 'http://127.0.0.1:18011/v1/uploads' \
  -H "X-API-Key: ${OCR_MCP_API_KEY}" \
  -H 'Content-Type: application/pdf' \
  --data-binary '@document.pdf'
```

成功响应包含 `file_id`。后续任务只传 `file_id`，不传本地路径。

### 3.2 创建解析任务

```bash
curl -X POST 'http://127.0.0.1:18011/v1/tasks' \
  -H "X-API-Key: ${OCR_MCP_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{
    "idempotency_key": "随机且不含业务信息的标识",
    "sources": [{"file_id": "上传返回的 file_id"}]
  }'
```

保存响应中的 `batch_id`。同一逻辑提交重试必须复用原幂等键。

### 3.3 查询进度

```bash
curl \
  -H "X-API-Key: ${OCR_MCP_API_KEY}" \
  'http://127.0.0.1:18011/v1/tasks/<batch_id>'
```

建议每 15 秒查询一次，只在状态、进度、阶段、成功数或失败数变化时展示更新。

主要阶段：

| 进度范围 | 阶段 |
|---|---|
| 0–12% | 上传、校验、排队 |
| 12–70% | MinerU 主解析 |
| 70–75% | 图片候选收集和分类 |
| 75–88% | Paddle 二次识别 |
| 88–94% | 结果合并 |
| 94–97% | 产物打包 |
| 97–100% | 发布与完成 |

### 3.4 下载产物

终态响应中的 `artifacts` 包含 `artifact_id`：

```bash
curl \
  -H "X-API-Key: ${OCR_MCP_API_KEY}" \
  -o result.zip \
  'http://127.0.0.1:18011/v1/artifacts/<artifact_id>'
```

下载后至少校验 ZIP 非空并包含 `final.md`。

## 4. MCP 工作流

MCP 只暴露：

1. `parse_documents`
2. `get_task_status`
3. `reparse_with_page_orientation`

本地路径不能直接传给远程 MCP。正确流程是：

```text
本地文件 → REST 上传 → file_id → parse_documents
         → get_task_status → artifact_id → REST 下载
```

推荐让智能体使用仓库内 `using-ocr-mcpserver` Skill 自动完成这条链路。

## 5. 方向处理

- 整份文档侧倒由预处理阶段识别和纠正。
- 少量局部旋转候选先显式分类方向，再确定性旋转并识别。
- 普通任务失败不得自动调用方向恢复。
- 只有用户确认方向异常页后，才使用
  `reparse_with_page_orientation` 和服务返回的恢复令牌。

## 6. 产物结构

典型 ZIP：

```text
artifact_manifest.json
content_list_v2.json
final.md
original_content_list_v2.json
secondary_ocr_audit.json
images/
mineru/
```

- `final.md`：面向使用者的最终 Markdown。
- `content_list_v2.json`：合并后的结构化结果。
- `original_content_list_v2.json`：MinerU 原始结构化快照。
- `secondary_ocr_audit.json`：二次识别与替换审计。
- `images/`：最终引用的图片。
- `mineru/`：受控保留的 MinerU 原始产物。

不要把产物正文写入应用日志。

## 7. 状态处理

- `completed`：批次完成。
- `completed_with_errors`：部分文件失败，仍下载全部可用产物。
- `failed`：没有可用结果，保留 `batch_id` 和稳定错误码。
- `cancelled`：任务被取消。

文件状态 `completed_with_warnings` 表示产物可用，但存在有限警告。警告不等于失败。

## 8. 常见问题

### 返回 `authentication_failed`

检查请求是否携带正确的 `X-API-Key`，以及生产容器是否使用同一密钥配置。不要在排查
输出中打印密钥。

### MCP 拒绝本地路径

这是预期行为。先调用 REST 上传接口取得 `file_id`，或使用
`using-ocr-mcpserver` Skill。

### 进度长时间停在 12%

大文件的 MinerU 主解析阶段可能长时间保持同一百分比。确认容器健康并继续按 15 秒
轮询，不要重复提交新任务。

### 任务在 87% 附近停留

该区间仍在处理图片候选。88% 后进入合并，94% 后进入打包。以最终任务状态为准。

### 大文件失败

记录 `batch_id`、稳定错误码、阶段、页数、大小和计数。不要输出正文。确认文件未超过
60 MiB、500 页和批次限制。
